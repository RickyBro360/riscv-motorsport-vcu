## 1. The project
===============================================================================

Title: "AI-Enabled RISC-V Based Motorsport Electronics Platform with Active
Aerodynamics, Telemetry, and Digital Twin for a 1:10 Scale Formula-Style RC Car"

### Architecture — LOCKED, do not propose changes to it

  Racing Engineer Station (laptop)
      FastAPI backend + SQLite, rule-based AI engineer + digital twin,
      Next.js dashboard. Ground radio: classic ESP32 + Ra-02 SX1278 on USB
           |
        LoRa 433 MHz (MODE B)  or  Wi-Fi (MODE A)
           |
  Raspberry Pi 4B — gateway only. Bridges CAN <-> ground, logs to CSV.
      Computes nothing that controls the car.
           |
        CAN 500 kbit/s
           |
  ESP32-C6 VCU — reads every sensor, drives every actuator.
      SOLE ACTUATOR AUTHORITY. Validates every input from the Pi/laptop.

The AI only ever RECOMMENDS or PROPOSES. The VCU validates confidence, age and
range, and decides. Never propose giving the Pi or the laptop direct actuator
control. The dashboard's Start run / Run motor / E-STOP / mode / calibration buttons are
REQUESTS that the VCU accepts or refuses (CONFIG_ACK) — same rule.

## 6. BUGS ALREADY FOUND AND FIXED — DO NOT RE-INTRODUCE
===============================================================================

1. GPIO10/11 DO NOT EXIST on the ESP32-C6-MINI-1 module.
2. GPIO22/23 are the on-board TCA9554 expander's I2C. Never start I2C there; FW 2.2+ only
   READS them as plain inputs for the KY-040 (every device on them only pulls low).
3. GPIO8 and GPIO9 are strapping pins and must be HIGH at reset (Hall RL moved to GPIO3,
   GPIO8 drives a servo with a 10k pull-up).
4. The backend ECHOES telemetry frames back. The Pi and bridge.py drain their WebSocket
   in a background task; the backend bounds each send to 0.5 s.
5. The 1-Wire bit-bang must NOT call pinMode() inside the timing slots: the pin is set
   OUTPUT_OPEN_DRAIN once.
6. LoRaRF's begin() never reads the chip. The Pi checks RegVersion (0x12).
7. The ground modem's status lines must be SLIP END-delimited.
8. The dashboard derives the backend URL from its own page host; CORS accepts private LAN.
9. The stall watchdog is PULSE-based (no rear pulse for 2.5 s at > 25 % duty).
10. The Pi forwards CONFIG_REPORTs in its own rotation, changed/ACKed keys first.
11. The ESP32-CAM serves only ONE client — the backend relay.
12. The flap stagger uses a `rear_changing_` flag, not a sentinel angle.
13. The twin's aero map must SATURATE in downforce while drag keeps rising.
14. (FW 2.2) The backend's latest frame is chosen by row id (not vehicle timestamp) and
    skips simulator frames — otherwise stale frames showed after a gateway restart.
    (FW 2.3: the recorder keeps that same row in memory; same rule.)
15. (FW 2.2) MOTOR_EN must not be on GPIO16 (U0TXD prints at boot): it is on GPIO19 and the
    FL flap servo took GPIO16 on rev B.
16. (FW 2.1.2) The Arduino IDE inserts its generated prototypes before the FIRST function in
    the .ino. No function definition (not even a constexpr helper) may sit above the struct
    definitions, or the build fails with "'X' does not name a type". Use macros there.
17. (2026-11-12) ~1 s of accidental 12 V killed the ESP32-C6 board. Before every power-up,
    meter-check that the 12 V side (adapter, INA260 IN+/IN-, L298N 12 V) touches nothing on
    VSYS, 3V3 or any MCU pin.
18. (FW 2.2.1) On the dual-core classic ESP32, noInterrupts() masks only the current core, so all
    tasks are pinned to ARDUINO_RUNNING_CORE (where the ISRs are attached). Keep it that way.
19. (FW 2.2.2) Prototype J1 pin order does not match the SN65HVD230 module (VCC,GND,CRX,CTX):
    plugged straight in, TX/RX are crossed. Fixed in firmware (VCU_PROTO_CAN_SWAPPED 1). Do not
    run older firmware with the module plugged in. Fix the footprint on the next PCB.
20. (FW 2.2.5) Never take a vTaskDelayUntil() reference before a long blocking step (self-test):
    the task then "catches up" without blocking, starves lower priorities, and the task watchdog
    reboots the MCU. Use loopWait() (xTaskDelayUntil + resync when it returns pdFALSE).
21. (FW 2.2.8) Do not poll the KY-040 from a low-priority task: it passes its middle state in < 1 ms
    and the poll misses it (count stays 0). FW 2.3: PCNT on both chips.
22. (FW 2.2.9) Ages of timestamps written by another task must be clamped (ageMs()): if that task
    ran after `now` was read, `now - t` wraps and raises a false critical WATCHDOG -> E-STOP.
23. (FW 2.3) The backend wrote every telemetry frame to SQLite ON the asyncio event loop and
    broadcast to viewers one after another: the dashboard lagged. Keep DB writes in to_thread,
    WAL on, and the broadcast concurrent.
24. (FW 2.3) The e-stop-reset self-test runs in the CONTROL task while the SENSOR task reads the
    same I2C / 1-Wire buses: every bus access holds g_i2c_mutex (recursive) / g_ow_mutex.
25. (FW 2.3) A failed self-test item must not park the car in FAULT for ever (FW 2.2 did: the flag
    never cleared). It is a WARNING now.
