Where builds usually go wrong

  • Servo plug on the wrong pins. The red wire must sit on the middle pin (+5V). The schematic headers currently put PWM in the middle. If a servo twitches, runs hot or does nothing, check this first.
  • No common ground. The CAN HAT's G, the L298N's GND, the buck's OUT− and every servo's brown wire must all reach the same ground. A missing CAN ground gives zero frames.
  • Buck not set before connecting. Many buck modules ship with the output near the input voltage. Set 5.0–5.2 V with nothing attached, then connect.
  • L298N ENA/ENB jumpers left on. The motors then ignore the PWM and run at full speed as soon as 12 V is applied.
  • 5 V on a 3.3 V sensor. Halls, DS18B20s, the encoder, the MPU6050, the INA260 logic and the CAN module all run from 3.3 V. On 5 V, their outputs push 5 V into ESP32 pins.
  • INA260 VBUS floating. The voltage reads 0 V and the VCU latches a fault.
  • Missing pull resistors. R5 (GPIO8 up): without it the board may not boot. R6 (GPIO17 down): without it the motor can run during reset. R1 (1-Wire up to 3.3 V): without it no DS18B20 is found.
  • Ra-02 on SPI0 or on 5 V. SPI0 belongs to the CAN HAT, so the radio must use SPI1. The Ra-02 is 3.3 V only, and needs an antenna before power-up.
  • CANH/CANL swapped or termination wrong. With power off, expect about 60 Ω across H and L.
  • Encoder lines treated as I²C. D22/D23 are also the on-board expander's bus. The firmware must never start I²C on them.

Build and test order

  1. Power chain, no loads. Adapter → fuse → INA260 → buck. Set the buck to 5.0–5.2 V and measure it.
  2. Ground star. Adapter −, buck −, then every block as you add it.
  3. VCU on USB only. status should report selftest=0x00.
  4. I²C. MPU6050 and INA260, then i2cscan: expect 0x40 and 0x68.
  5. Halls, DS18B20s, encoder. Spin each wheel and watch status. Then run ds and tempmap.
  6. Servos, linkages off. Move each one with servo <id> 20, then calibrate the rear pair.
  7. L298N and motors, wheels free. motor 30: both wheels forward, current under 2 A.
  8. CAN to the Pi. sudo setup/can_up.sh reports which canX has the VCU.
  9. Radios. Antennas on, Pi gateway, then bridge.py on the laptop.
  10. Camera. Paste its stream URL into the dashboard.
